### Build Fixes

#### YAML Error — kint-joe.md
`site/soldiers/kint-joe/kint-joe.md` had `--` instead of `---` as the closing YAML delimiter (line 55). This blocked the entire build (0 files written). Fixed by adding the missing dash.

#### EPERM on Mounted Filesystem
The `_site` directory sits on a FUSE-mounted volume that allows writes but blocks `unlink`. Eleventy's passthrough copy calls `unlink` before copying each file, which fails with EPERM on every passthrough target that already exists in `_site`.

Fix: disabled all source-content passthrough copies in `.eleventy.js`. These directories (`soldiers`, `documents`, `anecdotes`, `events`, `admin`) are processed as templates — their raw `.md` source files don't need to be served from `_site`. The `assets` passthrough is also disabled since those files (CSS, JS, images) are already current in `_site` and don't change between sessions. The only remaining EPERM error at the end of each build is the assets passthrough, which can be ignored — assets are already correct.

```javascript
// .eleventy.js — all passthrough copies disabled for FUSE mount compatibility
// eleventyConfig.addPassthroughCopy("admin");
// eleventyConfig.addPassthroughCopy("soldiers");
// eleventyConfig.addPassthroughCopy("documents");
// eleventyConfig.addPassthroughCopy("anecdotes");
// eleventyConfig.addPassthroughCopy("events");
```

**Note for future sessions:** If assets (CSS/JS) are updated, copy them manually to `_site/assets/` or re-enable the passthrough temporarily on a machine where `_site` is not on a FUSE mount.

### Template Fixes

#### Anecdote Breadcrumb — Hardcoded Miller Link
`site/_includes/layouts/anecdote.njk` had a hardcoded breadcrumb pointing to `miller-marvin-dale`. Fixed to dynamically look up the first entry in `soldiers[]` against `collections.soldiers` and render the correct name and link. Works for any anecdote going forward.

#### Verbal Accounts Tab — Referenced Verbal Documents Not Surfacing
`site/_includes/layouts/soldier.njk` — Verbal Accounts tab only showed documents where the soldier was the `author`. Documents where the soldier appears in `contains[]` (type `verbal`) were not shown.

Added a `referencedVerbalDocs` pass:
- Iterates `soldierDocs.referenced` (populated by the crawler from `contains:`)
- Filters to `type == "verbal"`
- Renders as "Accounts Mentioning [First Name]" section in the Verbal Accounts tab

Result: the Dillon memorial speech now surfaces on Drinkard's, Cardwell's, and Hall's profiles.

#### Document Template — Referenced Soldiers Not Rendering
`site/_includes/layouts/document.njk` — the Referenced section in the Soldiers tab iterated `contains` treating each item as a plain slug string. But every document uses `{slug, name}` objects in `contains:`. Soldier lookup `s.data.slug == soldierSlug` never matched.

Fixed to extract `.slug` from each item:
```nunjucks
{% for item in contains %}
  {% set soldierSlug = item.slug if item.slug else item %}
  {% for s in collections.soldiers %}
    {% if s.data.slug == soldierSlug %}
```

#### Document Crawler — contains[] Objects Not Indexed
`site/_data/_crawlDocuments.js` — same root bug as the document template. The crawler iterated `fm.contains` treating each item as a plain string, so `referenced` was never populated (items landed under `[object Object]` keys).

Fixed:
```javascript
for (const item of fm.contains) {
  const slugStr = (typeof item === 'string') ? item : (item && item.slug);
  if (!slugStr) continue;
  ensureSlug(slugStr);
  bySlug[slugStr].referenced.push(doc);
}
```

## Architecture Notes

**CRLF** — repo built on Windows, all files use `\r\n`. Edits via Python `open(path, 'rb')` / `open(path, 'wb')` to preserve line endings.

**contains: format** — always `{slug, name}` objects, never plain strings. Both the crawler and document template now handle this correctly.

**Decorations policy:**
- Confirmed sources → `decorations:`
- Documented but no primary source → `decorations_unconfirmed:` with inline comment
- Non-hostile death (Fanning, Colburn, Jeffries — crash) → no Purple Heart regardless
- NDSM / VSM / VCM treated as universal confirmed for all Vietnam-era soldiers

**R2 key format** — `soldiers/[slug]/[subfolder]/[filename]`. Served at `/media/photos/soldiers/[slug]/[subfolder]/[filename]`.

**Soldier slug format** — `lastname-firstname` or `lastname-firstname-middlename`.

**Deployment** — `npx wrangler deploy` from `site/`. Push via GitHub Desktop only.

**Admin server** — `npm start` from `admin/`. Requires `.env` with `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `CLOUDFLARE_ACCOUNT_ID`.

**R2 buckets:**
- `angryskipperarchive-photos` — public media, served at `/media/photos/`
- `angryskipperarchive-documents` — documents
- `angryskipperarchive-submissions` — public form submissions, private

**_private/contacts.json** — gitignored; holds phone/email/address for living contacts. NEVER commit PII to .md files.
